# AI Tabletop Framework

Веб-фреймворк для проведения настольных ролевых игр (TRPG) в кругу друзей.
Роль Гейм-Мастера выполняет языковая модель через OpenAI-совместимый API.

## Установка

1. Установите [Poetry](https://python-poetry.org/docs/#installation).
2. Скопируйте проект и установите зависимости:

```bash
cd AITTF
poetry install
```

3. Создайте `AITTF/.env` (скопируйте из `.env.example`):

```env
API_KEY=your_api_key_here
BASE_URL=https://opencode.ai/zen/v1
MODEL=deepseek-v4-flash-free
```

Для смены провайдера укажите `BASE_URL` другого OpenAI-совместимого API:
| Провайдер | BASE_URL | MODEL |
|-----------|----------|-------|
| opencode.ai | `https://opencode.ai/zen/v1` | `deepseek-v4-flash-free` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `cognitivecomputations/dolphin3.0-r1-mistral-24b:free` |
| LM Studio (локально) | `http://localhost:1234/v1` | `*` |

## Запуск

```bash
cd AITTF
poetry run uvicorn web.main:app --host 0.0.0.0 --port 8000
```

Для доступа с других устройств в локальной сети узнайте IP сервера (`ipconfig` / `ip a`) и откройте `http://<IP>:8000`. Фаерволл должен разрешать порт 8000.

## Как играть

### 1. Лобби

Откройте `http://localhost:8000` — попадёте в лобби.
- Введите имя персонажа и нажмите **Добавить** — игрок появится в сетке слотов.
- Можно добавить любого количества игроков (от 1).
- Кнопка **Начать игру** появится автоматически, когда есть хотя бы один игрок.

### 2. Предыстории

После перехода в режим сбора предысторий каждый игрок заполняет свой бэкстори. Когда все предыстории готовы, становится доступна кнопка **Сгенерировать мир**.

### 3. Генерация мира

LLM анализирует концепты и предыстории всех персонажей и генерирует:
- **Сеттинг** — название и описание мира
- **Глобальный конфликт** — завязка сюжета и общая цель для группы
- **Кастомные характеристики** — 3 уникальных для этого мира стата
- **Классы/архетипы** — уникальная роль для каждого персонажа
- **Вступительный текст** — атмосферная сцена, погружающая в мир

Сгенерированные сеттинг и конфликт выводятся в чат отдельными сообщениями с подписями. Кнопка блокируется на время генерации.

### 4. Игровой процесс

- **Чат** — поле «Сказать» для реплик персонажа.
- **Действия** — кнопка «Заявить действие» для официальных ходов.
- **Таймер** — 15-секундное окно после каждого сообщения или действия, в течение которого игроки могут дописать свои фразы, не триггеря LLM на каждый чих. При истечении накопленный контекст отправляется на обработку.
- **Блокировка формы** — на время генерации ответа AI ввод и кнопки блокируются.
- **Обновления** — WebSocket `/ws/chat` доставляет сообщения, статусы, панель игроков и таймер без перезагрузки.

### 5. Админ-панель

`/admin` — редактирование HP игроков, переключение статуса игры (exploration / combat). Все изменения применяются через HTMX без перезагрузки страницы; плашка статуса и кнопка переключения обновляются динамически.

### 6. Сброс игры

Кнопка **Сбросить партию** в лобби, на странице выбора и в игровом интерфейсе — очищает БД и возвращает в лобби. Срабатывает только после подтверждения (HTMX `hx-confirm`).

## Особенности интерфейса

- **Автоскролл чата** — при отправке принудительный скролл вниз; при получении — только если пользователь не листал вверх.
- **Кнопка** `↓` — показывается зелёной, если пользователь отмотал вверх; становится красной с пульсацией, если пришли новые сообщения.
- **HTMX + WebSocket** — чат, панель игроков, статус игры и таймер обновляются в реальном времени через WebSocket и OOB-замены.
- **Таймер** — 15-секундное окно после каждого сообщения или действия: пока таймер не истёк, игроки могут дописать свои фразы, и отправка к LLM не происходит при каждом чихе. При истечении отправляется накопленный контекст.
- **Лобби** — сетка слотов игроков, добавление/удаление через HTMX, флаг `players-flag` управляет видимостью кнопки «Начать игру» через CSS `:has()`.

## Структура проекта

```
AITTF/
├── __init__.py
├── .env.example          # Шаблон переменных окружения
├── .gitignore
├── init_game.py          # Консольная инициализация (резервная)
├── test_llm.py           # Тест вызова LLM
├── pyproject.toml        # Зависимости (FastAPI, uvicorn, httpx, jinja2, ...)
├── db/
│   ├── __init__.py
│   └── database.py       # SQLite — инициализация, CRUD, таймеры
├── models/
│   ├── __init__.py
│   └── models.py         # Pydantic-схемы
├── llm/
│   ├── __init__.py
│   ├── ai_generator.py   # HTTP-вызов LLM (httpx)
│   ├── context_builder.py# Сборка системного промпта
│   └── turn_processor.py # Парсинг ответа AI, TurnResponse
├── core/
│   ├── __init__.py
│   ├── game_engine.py    # Броски кубиков, инициатива, бой
│   └── initialization.py # Создание игровой сессии
└── web/
    ├── __init__.py
    ├── main.py           # FastAPI-сервер, WebSocket, HTMX-эндпоинты
    └── templates/
        ├── lobby.html    # Лобби (добавление игроков, старт игры)
        ├── slots.html    # Сетка слотов с карточками игроков
```

### Технологии

| Компонент | Что используется |
|-----------|-----------------|
| Сервер | FastAPI + Uvicorn |
| Фронтенд | HTMX 2.x + Tailwind CSS (CDN) |
| Шаблоны | Jinja2 |
| База данных | SQLite |
| Схемы | Pydantic v2 |
| HTTP-клиент | httpx |
| WebSocket | `websockets` (Python) + WebSocket API |
| Модель | deepseek-v4-flash-free через opencode.ai |
