# AGENTS.md

Инструкции для ИИ-агентов, работающих в этом репозитории. Загружаются автоматически при сканировании проекта.

## Проект

AITTF (AI Tabletop Framework) — веб-фреймворк для настольных ролевых игр: роль Гейм-Мастера выполняет языковая модель через OpenAI-совместимый API. Python + FastAPI, шаблоны Jinja2, зависимостей минимум. Пользовательский сценарий и настройка провайдеров — в `README.md`.

Принцип LLM-взаимодействия: **минимум на входе, точный результат** — не раздувать контекст запроса без нужды, изменения в промптах и сборке контекста держать в рамках этого баланса.

## Структура

- `web/` — FastAPI-приложение (`main.py`) и Jinja-шаблоны (`templates/`)
- `llm/` — работа с моделью: генератор, сборка контекста, обработка хода
- `core/` — игровой движок и инициализация
- `db/` — хранилище
- `models/` — модели данных
- `scripts/` — служебные скрипты проверок

План развития интерфейса ведётся в `UI_ROADMAP.md` (правки UI — только в шаблонах, без роста нагрузки на LLM).

## Запуск и проверки

```sh
python -m poetry install
python -m poetry run uvicorn web.main:app --host 0.0.0.0 --port 8000
python scripts/check_file_size.py   # рэтчет размеров файлов
python -m ruff check .              # линтер
```

`.env` создаётся из `.env.example` (ключи API). CI гоняет рэтчет на каждый push/PR; локальные pre-commit хуки включаются один раз на клон:

```sh
git config core.hooksPath hooks
```

## Сдерживание роста файлов

Исходники не должны разрастаться: новые `.py`-файлы — до **1000 строк**. `web/main.py` перерос лимит исторически и запинен в `scripts/source-file-size-baseline.json`: коммит, оставивший файл больше записанного числа, отклоняется; похудевший файл требует понижения его записи там же; дорос до лимита — запись удаляется.

Лимит, расширения и исключённые каталоги настраиваются в том же JSON — код чекера менять не нужно.
